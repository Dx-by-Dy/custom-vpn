## Каскад: хаб + exit'ы на sing-box

Сотрудники подключаются к хабу, хаб отправляет трафик по маршруту
пользователя. Маршрут — пара «сервер + исходящий IP», так что несколько
маршрутов могут вести на один exit с разными IP.

Решения:

- sing-box везде (хаб и exit'ы) вместо xray + hysteria: один движок, один
  формат конфига, маршрутизация по пользователю (`auth_user`) одинаково для
  VLESS и hy2. Конфиги собираются через `jq`.
- Хаб→exit — VLESS REALITY Vision (на этом участке есть цензура).
- Роль в `.env`: `ROLE=hub` (по умолчанию, как сейчас) или `ROLE=exit`
  (только sing-box, без домена, сертификата и подписок).
- Выход с самого хаба — встроенный exit `local` (в том числе с несколькими IP
  хаба). Нынешняя одиночная установка = хаб, у которого все пользователи на
  `local`.
- Exit не знает сотрудников: хаб получает по UUID на каждый IP exit'а, exit
  маршрутизирует по этому UUID на `inet4_bind_address`.
- Exit недоступен — у пользователя нет интернета, тихого переключения на
  другой маршрут нет.
- Правила по назначению общие для всех пользователей (например, RU → `local`).

### Требования к маршрутизации и управлению (2026-11-01)

Главная угроза — полная блокировка доступа к серверам. Поэтому управление
отделено от самой системы: схему правят на ноутбуке и публикуют в DNS, узлы
сами ее забирают. Схема меняется редко (1–2 раза в неделю).

Маршрутизация:

- маршрут — имя выхода: `local` (с хаба), `cz1/a` (exit + псевдоним IP),
  позже `hub2/...` (через соседний хаб). IP знает только сам exit (псевдонимы
  его IP); остальные узлы находятся по доменам (A-записи), переезд узла —
  смена A-записи, без правки схемы;
- общее правило: RU → `local` (домены `.ru .su .рф` + geosite-ru, IP по
  geoip-ru после resolve на хабе);
- не RU — строго по маршруту человека (или его группы); нет маршрута — наружу
  ничего, кроме RU (fail-closed);
- группы заложены сразу (маршрут группы, личный маршрут сильнее).

Управление (control):

- control — не сервер, а каталог состояния на ноутбуке (`./vpn.sh ctl ...`):
  пользователи, группы, маршруты, токены exit'ов, хабы и их ключи;
- состояние публикуется снимком: JSON → сжатие → шифрование → подпись
  ed25519 → TXT-записи. Куски под номером версии (`v<N>-<i>`), потом
  переключается одна запись `head`; версия только растет (старый снимок не
  подсунуть). Пароль/токен DNS-панели есть только на ноутбуке, на хабах —
  только публичный ключ control и ключ расшифровки;
- хаб опрашивает `head` через несколько резолверов (DoH и обычные — подпись
  делает резолвер неважным), при ошибке работает на последнем хорошем снимке;
  синхронизация никого не отключает, отключает только явное удаление;
- тот же снимок можно применить руками: `ssh hub ./vpn.sh state apply < file`
  (если DNS недоступен или нужно срочно);
- DNS: dnsmanager (по паролю → токен авторизации, затем правка записей);
  проверить API, лимит длины TXT и числа записей;
- exit'ам синхронизация не нужна: все хабы используют один набор ключей
  exit'а (токен вводится один раз в control); клиенты берут конфиг из подписки;
- одиночный хаб без control работает как сейчас (`user add` на самом хабе).

Открытые вопросы: исключения из «RU → local»; может ли один IP быть у
нескольких людей и разные IP на разные сайты одному человеку; client —
процессы хоста или docker-контейнеры, нужен ли tun; подписка при нескольких
хабах (общий домен `sub.` с A-записью на живой хаб?).

### Этап 3. Маршруты на одном хабе — сделано

`exit add NAME TOKEN|del|list`, `group add|route|del|list`, `user add
--group/--route`, `user route|group`, `route list`; `exits.conf`,
`groups.conf`, `routing.conf`; `ROUTE_DEFAULT` (нет ключа в `.env` — `local`,
как раньше). На exit'е `EXIT_IPS=ИМЯ=IP`, имена в токене. Списки RU
(geosite-category-ru, geoip-ru от SagerNet) в `data/rule-sets/`, обновляются
таймером, при недоступном GitHub — через exit. `check` на хабе: каждый
маршрут, `none` и RU через него, свежесть списков, пользователи без маршрута.

Важное из проверки: после `resolve` sing-box шлет дальше IP, а не имя —
поэтому хаб резолвит только то, что уходит с него (RU и `local`), а на exit
идет имя. geoip-ru срабатывает только на соединения по IP. Российский
провайдер тормозит часть IP Cloudflare (ipify), поэтому `local` проверяется
через `ip.beget.ru`.

Проверено (хаб — локально в podman, exit — 109.172.8.54 с двумя IP):
группа / свой маршрут / `ROUTE_DEFAULT` / `none` выходят каждый со своего IP
(VLESS и hy2, TCP и UDP); RU у всех с хаба, в том числе у `none`; соединение
к российскому IP без имени — `local`; localtest.me и 127.0.0.1 закрыты;
переименование IP на exit'е и падение exit'а — без интернета, кроме RU, без
подмены IP, `check` падает; старый ключ после `rotate` идет тем же маршрутом;
переход со старого `.env` через `init`. На настоящем хабе — вместе с
развертыванием (этап 7: docker + nginx `stream` на 91.219.150.99).

## Отдельные подписки под клиенты (косметика)

Сейчас все клиенты получают одну подписку `/<token>/sub` с заголовками
`profile-title: base64:…` и `profile-update-interval: 12`. Hiddify и NekoBox
показывают ее нормально, V2Box — нет: имя подписки «import sub (N)» и лимит 50 GB.

Пробовали (599542b, откачено) отдавать всем:

```
Content-Disposition: attachment; filename="SVOi"
profile-title: SVOi                     # без base64 для ASCII-имен
subscription-userinfo: upload=0; download=0; total=0; expire=0
```

Что вышло:

| Клиент   | Результат                                                                |
| -------- | ------------------------------------------------------------------------ |
| V2Box    | объем — бесконечность, срок — бессрочно; имя все равно «import sub (N)»   |
| NekoBox  | «истекает 1970.01.01» — `expire=0` понимает буквально                     |
| Hiddify  | лимит 857.03 GiB вместо «без лимита» на `total=0`                         |

Идея: отдельные адреса с заголовками под конкретный клиент, например
`/<token>/sub/v2box` с `subscription-userinfo` (и тем, что V2Box берет как имя),
а `/<token>/sub` оставить как есть. Кнопка V2Box на странице импорта ведет на
свой адрес.

Что выяснить:

- откуда V2Box берет имя подписки: параметр `name` в `v2box://install-sub` он,
  похоже, игнорирует, `profile-title` (plain и base64) и `Content-Disposition` — тоже;
  проверить `#name` в URL подписки, заголовок `profile-web-page-url`, имя в
  первой строке подписки;
- как V2Box показывает квоту без `expire` и с очень большим `total`
  (вдруг хватит одного адреса для всех без `expire=0`);
- откуда у Hiddify 857.03 GiB при `total=0`.

## VLESS без DNS: `VLESS_ADDRESS`

Xray не нужен ни домен, ни сертификат, но в `vless://` адресом стоит `DOMAIN`,
поэтому пока нет A-записи (или пока она не разошлась по резолверам) VLESS
не подключить. Настройка `VLESS_ADDRESS` в `.env` — адрес в VLESS-ссылке,
по умолчанию `DOMAIN`; можно поставить IP сервера. `./vpn.sh links NAME`
печатает такую ссылку для ручного импорта. Подписка и hysteria без DNS
все равно не работают (им нужен сертификат на `DOMAIN`). Минус IP навсегда:
при переезде ссылки не следуют за A-записью, только через обновление подписки.

## Маршрутизация по SNI, если 443/tcp занят другим сайтом — сделано (`VLESS_LISTEN`)

nginx `stream` + `ssl_preread` на 443: SNI из `REALITY_SNI` → sing-box на
локальном порту, остальное → сайты. Сайтам нужен `proxy_protocol` (иначе они
видят всех как 127.0.0.1), а sing-box его не принимает — поэтому VPN-ветка
через промежуточный `server` с `listen ... proxy_protocol`, который заголовок
снимает. Минус: все `listen 443` сайтов переезжают на локальный порт.
Нужно для хаба 91.219.150.99 (там nginx-сайты на 443) — или `VLESS_PORT` != 443.
