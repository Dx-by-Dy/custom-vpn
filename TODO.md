## Каскад: хаб + exit'ы на sing-box

Все сотрудники подключаются к одному хабу, хаб отправляет трафик по маршруту
пользователя. Маршрут — пара «сервер + исходящий IP», так что несколько
маршрутов могут вести на один exit с разными IP.

Решения:

- sing-box везде (хаб и exit'ы) вместо xray + hysteria: один движок, один
  формат конфига, маршрутизация по пользователю (`auth_user`) одинаково для
  VLESS и hy2. Конфиги собираются через `jq`.
- Хаб→exit — VLESS REALITY Vision (на этом участке есть цензура).
- Роль в `.env`: `ROLE=hub` (по умолчанию, как сейчас) или `ROLE=exit`
  (только sing-box, без домена, сертификата и подписок).
- Выход с самого хаба — встроенный exit `local` (в том числе с несколькими IP
  хаба). Нынешняя одиночная установка = хаб, у которого все пользователи на
  `local`.
- Exit не знает сотрудников: хаб получает по UUID на каждый IP exit'а, exit
  маршрутизирует по этому UUID на `inet4_bind_address`.
- Exit недоступен — у пользователя нет интернета, тихого переключения на
  другой маршрут нет.
- Правила по назначению общие для всех пользователей (например, RU → `local`).

### Этап 0. Проверка sing-box (до кода)

На тестовых портах, не трогая рабочий сервис:

- текущие клиенты (Hiddify, NekoBox, V2Box) подключаются к sing-box без
  переимпорта: VLESS REALITY Vision с теми же ключами и UUID, hy2 с тем же
  `user:password` (в sing-box — паролем целиком);
- self-steal: умеет ли REALITY в sing-box слать PROXY protocol при fallback
  (`REALITY_XVER=1`); если нет — решить, что делать (nginx `stream` перед ним?);
- `auth_user` работает для обоих inbound'ов, masquerade у hy2, UDP через VLESS
  до exit'а, `inet4_bind_address`;
- зафиксировать версию sing-box.

Результаты (2026-11-01, sing-box 1.14.4, хаб 91.219.150.99 RU → exit 109.172.8.54 CZ):

- ключи REALITY из `xray x25519` подходят sing-box как есть;
- к sing-box подключаются xray 26.3 (ядро V2Box), nekobox core 1.13 (sing-box)
  по VLESS и hy2, официальный hysteria 2.12 c `auth: user:password` — значит,
  нынешние ссылки работают без переимпорта; осталось проверить на телефонах
  (Hiddify, V2Box, NekoBox);
- `auth_user` маршрутизирует одинаково для VLESS и hy2; UDP (NTP) проходит
  и напрямую, и через хаб→exit; `inet4_bind_address` соблюдается (чужой адрес
  дает `bind: cannot assign`); мертвый exit — ошибка, а не обход;
- после `resolve` домен сохраняется: `domain_suffix ru → direct` срабатывает;
- приватные адреса: `ip_is_private` видит только IP, поэтому `resolve` нужен
  там, где трафик выходит (на хабе — только для того, что идет в `local`,
  на exit'е — для всего); `localtest.me` → 127.0.0.1 блокируется в обоих местах;
- masquerade hy2 (proxy) работает;
- **PROXY protocol sing-box не умеет**: REALITY шлет цели голый ClientHello,
  в dial/listen-полях такой опции нет. Self-steal с настоящими IP посетителей
  (`REALITY_XVER=1`) в нынешнем виде невозможен;
- память: sing-box 63 MB на хабе (2 inbound'а + 3 маршрута), 37 MB на exit'е.

### Этап 1. Хаб на sing-box, поведение как сейчас

Шаблон sing-box вместо `xray.json` / `hysteria.yaml`, `render` через `jq`
+ `sing-box check`; `init` (ключи через `sing-box generate`), `update images`,
`check`, `uninstall` под новый образ. Существующие установки переезжают через
`update repo` + `up` без смены ссылок. Выпускается отдельно.

### Этап 2. Роль exit

`ROLE=exit ./vpn.sh deploy`: без домена / caddy / подписок, находит публичные
IP хоста и спрашивает, какие использовать. `hubs.conf`, `hub add|del|list`;
`hub add NAME` печатает одну строку-токен (адрес, публичный ключ, short id,
UUID на каждый IP). Свой `REALITY_SNI` для exit'а, `check` для этой роли.

### Этап 3. Маршруты на хабе

`routes.conf`, `exit add NAME TOKEN|del|list`, `route list`; встроенный
`local`. `user add NAME --route R`, `user route NAME R`, `ROUTE_DEFAULT`
в `.env`; назначения хранятся отдельно от `users.conf` (не копировать их
в строки ротированных ключей). `check` проверяет каждый маршрут через
локальный socks-inbound и сверяет выходной IP с ожидаемым.

### Этап 4. Правила по назначению

`rules.conf`, по порядку до первого совпадения: блок приватных сетей и
BitTorrent → правила по назначению (`domain_suffix ru,su,xn--p1ai → local`,
`rule_set geoip-ru → local`) → маршрут пользователя → `ROUTE_DEFAULT`.

### Этап 5. Обвязка

`firewall` на exit'е — опционально 443 только для IP хабов. README, раздел
«Удаление» для обеих ролей.

## Отдельные подписки под клиенты (косметика)

Сейчас все клиенты получают одну подписку `/<token>/sub` с заголовками
`profile-title: base64:…` и `profile-update-interval: 12`. Hiddify и NekoBox
показывают ее нормально, V2Box — нет: имя подписки «import sub (N)» и лимит 50 GB.

Пробовали (599542b, откачено) отдавать всем:

```
Content-Disposition: attachment; filename="SVOi"
profile-title: SVOi                     # без base64 для ASCII-имен
subscription-userinfo: upload=0; download=0; total=0; expire=0
```

Что вышло:

| Клиент   | Результат                                                                |
| -------- | ------------------------------------------------------------------------ |
| V2Box    | объем — бесконечность, срок — бессрочно; имя все равно «import sub (N)»   |
| NekoBox  | «истекает 1970.01.01» — `expire=0` понимает буквально                     |
| Hiddify  | лимит 857.03 GiB вместо «без лимита» на `total=0`                         |

Идея: отдельные адреса с заголовками под конкретный клиент, например
`/<token>/sub/v2box` с `subscription-userinfo` (и тем, что V2Box берет как имя),
а `/<token>/sub` оставить как есть. Кнопка V2Box на странице импорта ведет на
свой адрес.

Что выяснить:

- откуда V2Box берет имя подписки: параметр `name` в `v2box://install-sub` он,
  похоже, игнорирует, `profile-title` (plain и base64) и `Content-Disposition` — тоже;
  проверить `#name` в URL подписки, заголовок `profile-web-page-url`, имя в
  первой строке подписки;
- как V2Box показывает квоту без `expire` и с очень большим `total`
  (вдруг хватит одного адреса для всех без `expire=0`);
- откуда у Hiddify 857.03 GiB при `total=0`.

## VLESS без DNS: `VLESS_ADDRESS`

Xray не нужен ни домен, ни сертификат, но в `vless://` адресом стоит `DOMAIN`,
поэтому пока нет A-записи (или пока она не разошлась по резолверам) VLESS
не подключить. Настройка `VLESS_ADDRESS` в `.env` — адрес в VLESS-ссылке,
по умолчанию `DOMAIN`; можно поставить IP сервера. `./vpn.sh links NAME`
печатает такую ссылку для ручного импорта. Подписка и hysteria без DNS
все равно не работают (им нужен сертификат на `DOMAIN`). Минус IP навсегда:
при переезде ссылки не следуют за A-записью, только через обновление подписки.

## Маршрутизация по SNI, если 443/tcp занят другим сайтом

nginx `stream` + `ssl_preread` на 443: SNI из `REALITY_SNI` → xray на локальном
порту, остальное → сайт. Заодно можно маскироваться под собственный сайт
(self-steal). Делать, когда появится сервер, где это нужно.
