# Client (ROLE=client): VPN для программ на сервере

Серверу, которому нужен выход наружу (бот, CI, скрипты), — sing-box на localhost: прокси socks5 + http на `CLIENT_LISTEN` (по умолчанию `127.0.0.1:2080`) через хабы подписки одного пользователя. Куда уходит трафик, решает хаб, как для телефона: RU — с хаба, остальное — по маршруту пользователя (у которого обычно свой маршрут, например `cz1/ip1`).

## Развертывание

```sh
# на клиенте:
git clone https://github.com/Dx-by-Dy/custom-vpn.git /opt/custom-vpn && cd /opt/custom-vpn
./vpn.sh client install-docker                    # если docker еще нет
CLIENT_SUB='https://hub1.example.ru:8443/<token>/sub https://hub2.example.ru:8443/<token>/sub' ./vpn.sh client deploy
```

`CLIENT_SUB` — ссылка на подписку или страницу импорта; можно несколько через пробел (ссылки разных хабов) — клиент берет первую, которая ответит. `CLIENT_LISTEN=127.0.0.1:2080`, `CLIENT_ROUTE` и `CLIENT_PROTOCOL` можно задать тут же или потом ([выбор маршрута и протокола](#выбор-маршрута-и-протокола)).

## Выбор маршрута и протокола

```sh
./vpn.sh client route                # маршруты пользователя, текущий отмечен *
./vpn.sh client route il1/ip1        # перейти на него; - : основной
./vpn.sh client protocol             # текущий протокол
./vpn.sh client protocol hy2         # auto | reality | hy2
```

| Протокол                   | Что выбирает `urltest`                                        |
| ---------------------------------- | -------------------------------------------------------------------------- |
| `auto` (по умолчанию) | самый быстрый хаб на любом из протоколов |
| `reality`                        | самый быстрый хаб на VLESS REALITY (tcp)                  |
| `hy2`                            | самый быстрый хаб на Hysteria 2 (udp)                     |

- Протокол сужает выбор, но хабы по-прежнему подменяют друг друга; с `reality` или `hy2` переключения на другой протокол нет, и если он здесь заблокирован, прокси не работает. После переключения команда проверяет прокси и предупреждает, если через него ничего не идет, но выбор не отменяет.
- Маршрут — один из списка пользователя (`control user route`), на каждый у него свой ключ. Если хаб не отдает такой маршрут, `client route` ничего не меняет. С маршрутом `il1/ip1+ru` RU тоже идет через exit, и `urltest` меряет хабы через него.
- Список маршрутов и проверка, что копия подписки того маршрута, работают с хабами на коде этой версии; со старыми `client route ИМЯ` работает, а список не показывается.
- Если в `.env` записан маршрут, которого нет в копии подписки, и хабы не отвечают, `up` откажет: иначе трафик ушел бы через другой маршрут. `check` в таком случае падает на строке `subscription`.

## Использование

```sh
curl -x socks5h://127.0.0.1:2080 https://api.ipify.org          # IP маршрута пользователя
curl -x socks5h://127.0.0.1:2080 https://ip.mail.ru | grep -oE '([0-9]+\.){3}[0-9]+' | head -1   # IP хаба (RU)
export HTTPS_PROXY=http://127.0.0.1:2080 HTTP_PROXY=http://127.0.0.1:2080   # для программ, которые понимают прокси
```

`socks5h` (имя резолвит прокси) — правильнее, чем `socks5`: так RU / не RU решает хаб по имени. Адреса частных сетей идут мимо прокси.

## Как работает

- Хабы отдают для каждого пользователя `…/<token>/sing-box.json` — VLESS REALITY и Hysteria 2 каждого хаба. Клиент кладет копию в `data/client/sub.json` и собирает `generated/sing-box.json`: `mixed` на `CLIENT_LISTEN` → `urltest` между хабами на выбранном протоколе (каждые 3 минуты меряет RU-адрес — то есть сам хаб) → самый быстрый.
- Если хаб пропал, через несколько минут трафик идет через другой; когда вернется — обратно на быстрейший.
- `vpn-maintenance.timer` раз в час (`prune`) обновляет подписку и перезапускает sing-box, если хабы или ключи поменялись (новый хаб, `user rotate`). Если ни один `CLIENT_SUB` не отвечает — работает на последней копии.
- Подписка с любого хаба содержит все хабы, поэтому новый хаб клиент подхватит сам.

## Проверка

```sh
./vpn.sh client check
```

```
containers   ok
subscription ok (cz1/ip1, protocol auto, via hub1.example.ru hub2.example.ru, refreshed 0h ago)
proxy        ok (127.0.0.1:2080: RU leaves as 203.0.113.10, the rest as 198.51.100.20)
```

`subscription` падает, если подписку не удавалось обновить больше 2 суток или копия другого маршрута; `proxy` — если через прокси не проходит даже RU (хабы недоступны). «the rest nowhere» при живом RU — у пользователя маршрут `none` или его exit не работает.

## Безопасность

- Прокси слушает только localhost. `CLIENT_LISTEN=0.0.0.0:2080` открыл бы его всем — тогда только за firewall'ом.
- `data/client/sub.json` — ключи пользователя (права 600). Утекли — в control `user del` + `user add`, новый `CLIENT_SUB` здесь (`.env`, затем `./vpn.sh client up`).
- Убрать: `./vpn.sh client uninstall`.
