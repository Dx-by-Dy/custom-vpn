# Exit (ROLE=exit): сервер, с которого трафик уходит в мир

Exit принимает только хабы (VLESS REALITY) и выпускает их трафик с одного из своих IP. Домен, сертификат и пользователи ему не нужны: о людях exit не знает ничего — какой IP использовать, хаб выбирает ключом (свой ключ на каждый IP).

## Развертывание

```sh
git clone https://github.com/Dx-by-Dy/custom-vpn.git /opt/custom-vpn && cd /opt/custom-vpn
./vpn.sh install-docker    # если docker еще нет
ROLE=exit ./vpn.sh deploy  # ключи, EXIT_IPS, запуск, таймер
./vpn.sh hub add main      # токен cvpn-exit:... для хабов
```

Токен вводится один раз — в [control](control.md#exit) (`./vpn.sh exit add cz1 'cvpn-exit:...'`) или на самостоятельном хабе — и годится всем хабам. Имя exit'а (`cz1`, `il1`) задается там же; принято «страна + номер».

## Настройки (`.env`)

| Переменная | Что это |
|---|---|
| `EXIT_IPS` | IP, с которых уходит трафик: `ИМЯ=IP` через запятую. `init` находит публичные IPv4 хоста сам и называет их `ip1`, `ip2`, ... Хабы видят их как маршруты `EXIT/ИМЯ` |
| `EXIT_ADDRESS` | адрес, к которому подключаются хабы (по умолчанию первый из `EXIT_IPS`) |
| `VLESS_PORT` | порт для хабов; 443 выглядит естественнее, но любой свободный работает (на `il1` — 9443, 443 у сайта) |
| `REALITY_SNI` | сайт, под который маскируется exit; участок хаб → exit проходит через DPI, так что лучше правдоподобный для страны и хостинга |
| `COMPOSE_PROJECT_NAME` | имя docker compose проекта, по умолчанию `vpn`. Если на хосте уже есть **другой** проект с именем `vpn` (например, старая установка VPN), задайте свое (`cvpn`): `up` делает `docker compose up --remove-orphans` и иначе снес бы чужие контейнеры. Однажды задав, не меняйте — контейнер пересоздастся |

Поменять IP или имя: правка `EXIT_IPS`, `./vpn.sh up`, затем `./vpn.sh hub token main` и новый токен — `exit add` с тем же именем в control. Пока токен не обновлен, маршруты с удаленными IP не работают (переключения на другой IP нет).

## Безопасность

- Трафик уходит только с IP своего ключа, маршрута по умолчанию нет. IPv6 закрыт (выход только с IPv4 из `EXIT_IPS`), приватные сети и адреса самого exit'а — тоже.
- `hub del NAME` — хаб с этим токеном сразу перестает подключаться (у всех хабов один токен `main`, так что это отключит все хабы: заведите отдельный токен, если нужно отключать хабы по одному). `hub list` — токены и их IP.
- `./vpn.sh firewall` откроет ssh, `VLESS_PORT` и спросит про остальные публичные сервисы (сайт на 80/443 и т. п.).

## Рядом с другими сервисами

Exit занимает только `VLESS_PORT`/tcp и `127.0.0.1:CHECK_PORT` (10800) — его можно ставить на сервер с сайтом или ботом. Если 443 у сайта — `VLESS_PORT` другой; если на хосте уже есть compose-проект `vpn` или `vpn-maintenance.timer` чужой установки — `COMPOSE_PROJECT_NAME`, и `init` + `up` вместо `deploy` (без таймера), пока чужая установка не убрана.

## Проверка и бэкап

- `./vpn.sh check`: контейнер, доступность `REALITY_SNI`, и для каждого IP из `EXIT_IPS` — что трафик через его ключ действительно выходит с него (запрос через локальный socks `CHECK_PORT`). Хабы в своем `check` проверяют путь до exit'а со своей стороны.
- Бэкапить `.env` и `hubs.conf`: с ними на новом сервере хабам ничего менять не нужно, кроме адреса (если он сменился — новый токен).
