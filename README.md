# custom-vpn

Xray (VLESS + REALITY + Vision) и Hysteria 2 в Docker, для быстрого развертывания на новом сервере.

| Сервис   | Порт     | Что делает                                                                    |
| -------- | -------- | ----------------------------------------------------------------------------- |
| xray     | 443/tcp  | VLESS REALITY, для посторонних выглядит как `REALITY_SNI` (по умолчанию music.yandex.ru) |
| hysteria | 443/udp  | Hysteria 2 (QUIC)                                                             |
| caddy    | 8443/tcp | подписки для клиентов (`SUB_PORT`)                                            |
| caddy    | 80/tcp   | только на время выпуска/продления сертификата Let's Encrypt (HTTP-01)         |

Caddy получает сертификат на `DOMAIN` и продлевает его; hysteria берет тот же сертификат и сама подхватывает обновленный.

Контейнеры работают в `network_mode: host` (без NAT для UDP), от root только ради портов < 1024, все остальные capabilities сброшены. Трафик клиентов в приватные сети и на сам хост заблокирован, BitTorrent в xray тоже.

## Развертывание

1. A-запись домена → IP сервера. **До запуска**, иначе caddy будет пытаться получить сертификат и упрется в лимиты Let's Encrypt.
2. На сервере:

   ```sh
   git clone <repo> /opt/custom-vpn && cd /opt/custom-vpn
   ./vpn.sh install-docker             # если docker еще нет
   cp .env.example .env && nano .env   # DOMAIN, ACME_EMAIL
   ./vpn.sh deploy                     # sysctl, ключи, первый пользователь, запуск, ссылки
   ```

`./vpn.sh` без аргументов показывает справку.

`deploy` генерирует ключи REALITY в `.env`, создает пользователя `default` в `users.conf`, ставит таймер `vpn-prune.timer` (чистит просроченные ключи после ротации) и выводит ссылки.

Перед запуском `up` проверяет, что нужные порты (443/tcp, 443/udp, `SUB_PORT`/tcp, 80/tcp) не заняты чужими процессами — например, если на сервере уже есть сайт. Если заняты — скажет кем и ничего не запустит. `XRAY_PORT` / `HYSTERIA_PORT` / `SUB_PORT` можно поменять в `.env`, 80/tcp — нельзя (нужен Let's Encrypt).

**Бэкапить нужно `.env` и `users.conf`** — все остальное воспроизводится из репозитория. С ними на новом сервере клиенты продолжат работать, достаточно перенести A-запись.

## Пользователи и подписки

У каждого пользователя свои ключи и своя ссылка на подписку:

```sh
./vpn.sh user add vasya    # создать и показать ссылки (+ QR, если стоит qrencode)
./vpn.sh user list
./vpn.sh links vasya       # показать ссылки еще раз
./vpn.sh user del vasya    # ключи и подписка перестают работать сразу
```

- `https://DOMAIN:8443/<token>/sub` — подписка (base64-список `vless://` + `hysteria2://`). Подходит для любого клиента: «Добавить подписку» → вставить URL. Клиенты сами ее обновляют, так что новые ключи и настройки дойдут до них без переимпорта.
- `https://DOMAIN:8443/<token>/` — страница с кнопками, которые сразу открывают приложение и добавляют подписку:

  - Hiddify — `hiddify://import/<url>#<name>`
  - NekoBox — `sn://subscription?url=<url>&name=<name>`
  - V2Box — `v2box://install-sub?url=<url>&name=<name>`

Все, кроме токенов пользователей, отдает 404. Добавление/удаление пользователя перезапускает xray и hysteria — у всех на секунду рвется соединение, клиенты переподключаются сами.

### Ротация ключей

```sh
./vpn.sh rotate vasya             # новые ключи, старые работают еще 24 часа
./vpn.sh rotate --all --grace 48  # всем, старые работают 48 часов
```

Ссылка на подписку не меняется. Пока старые ключи работают, клиенты успевают обновить подписку через еще живой туннель — не нужно отключать VPN, чтобы ее обновить. Просроченные ключи удаляет `vpn-prune.timer` (раз в час).

Если ссылка **утекла** — `rotate` не поможет (по старой ссылке получат и новые ключи): `user del` + `user add` и отправить человеку новую ссылку.

## Обновление

```sh
./vpn.sh update images   # новые версии xray / hysteria / caddy
./vpn.sh update repo     # новый код этого репозитория с GitHub
```

`update images` показывает новые версии, спрашивает и обновляет. Образы, которые уже вышли на GitHub, но еще не опубликованы в registry, пропускаются. Если с новой версией конфиг не проходит проверку или контейнеры не стартуют — версии в `.env` откатываются.

`update repo` забирает `main` из публичного репозитория (`REPO_URL` / `REPO_BRANCH` в `.env`, чтобы поменять), показывает новые коммиты и файлы, которые изменятся, предупреждает о перезапуске контейнеров и спрашивает. Каталог, развернутый без git, при первом запуске становится git-checkout'ом (git ставится сам). Состояние сервера не трогается: `.env`, `users.conf`, `data/` (сертификаты) и `generated/` — перед обновлением `.env` и `users.conf` копируются в `backups/`, после — сверяются; если upstream вдруг начнет их отслеживать, обновление откажется. Локальные правки отслеживаемых файлов (шаблоны, `compose.yaml`) будут потеряны — об этом тоже предупредит.

## Firewall (опционально)

```sh
./vpn.sh firewall --dry-run   # только показать план
./vpn.sh firewall             # включить ufw
```

Открывает ssh (порт берется из sshd), порты VPN и спрашивает про остальные сервисы, которые сейчас слушают публичные адреса (другой сайт и т.д.), — по умолчанию оставляет их доступными. Все остальное входящее закрывается. Затем предлагает отключить вход по SSH-паролю — только если в `authorized_keys` есть ключи.

## Команды

| `./vpn.sh …`                        |                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `help` (по умолчанию)               | справка                                                                  |
| `deploy`                            | `tune` + `init` + `up` + таймер + `links`                                |
| `init`                              | создать `.env`, догенерировать ключи, создать первого пользователя       |
| `up`                                | `render` + проверка портов + запуск/перезапуск измененных сервисов       |
| `down` / `logs`                     | остановить / смотреть логи                                               |
| `user add\|del\|list`               | пользователи                                                             |
| `links [NAME]`                      | ссылки всех пользователей или одного                                     |
| `rotate NAME\|--all [--grace H]`    | новые ключи, старые работают еще H часов (24)                            |
| `update images`                     | обновить образы до последних версий                                      |
| `update repo`                       | обновить код с GitHub (пользователи и ключи сохраняются)                 |
| `firewall [--dry-run]`              | ufw + отключение SSH-пароля                                              |
| `tune`                              | BBR + увеличенные UDP-буферы (`/etc/sysctl.d/99-vpn.conf`)               |
| `render`                            | собрать `generated/*` из `templates/*`, проверить конфиги xray и caddy   |
| `prune`                             | удалить просроченные ключи (это делает таймер)                           |
| `install-docker`                    | поставить docker через get.docker.com                                    |

`-y` — ответить «да» на все вопросы (для скриптов).

Поменять настройки: правим `.env` или `templates/*`, затем `./vpn.sh up`.

## Переезд с systemd-установки

Если xray и hysteria стоят как systemd-сервисы, они держат порты (`up` об этом скажет):

```sh
systemctl disable --now xray hysteria-server
./vpn.sh deploy
```

Однопользовательский `.env` (с `XRAY_UUID` / `HYSTERIA_PASSWORD` / `SUB_TOKEN`) `init` переносит в пользователя `default` с той же ссылкой на подписку. VLESS продолжит работать сразу, hysteria — после обновления подписки в клиенте (формат авторизации поменялся на `user:password`).
