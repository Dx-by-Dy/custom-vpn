# custom-vpn

VLESS (REALITY + Vision) и Hysteria 2 на sing-box в Docker, для быстрого развертывания на новом сервере.

| Сервис   | Порт     | Что делает                                                                    |
| -------- | -------- | ----------------------------------------------------------------------------- |
| sing-box | 443/tcp  | VLESS REALITY, для посторонних выглядит как `REALITY_SNI` (по умолчанию music.yandex.ru) |
| sing-box | 443/udp  | Hysteria 2 (QUIC)                                                             |
| caddy    | 8443/tcp | подписки для клиентов (`SUB_PORT`)                                            |
| caddy    | 80/tcp   | проверки Let's Encrypt (HTTP-01), держится постоянно; `ACME_HTTP_PORT` — если 80 занят сайтом |

Caddy получает сертификат на `DOMAIN` и продлевает его; hysteria берет тот же сертификат, sing-box сам подхватывает обновленный. VLESS сертификат не нужен: при первой установке он работает сразу, а hysteria включается, как только caddy получит сертификат (`up` ждет до трех минут).

Контейнеры работают в `network_mode: host` (без NAT для UDP), от root только ради портов < 1024, все остальные capabilities сброшены. Трафик клиентов в приватные сети и на адреса самого сервера заблокирован (в том числе через домены вроде `localtest.me` → 127.0.0.1: sing-box сначала резолвит имя), BitTorrent тоже.

## Развертывание

1. A-запись домена → IP сервера. **До запуска**, иначе caddy будет пытаться получить сертификат и упрется в лимиты Let's Encrypt.
2. На сервере:

   ```sh
   git clone <repo> /opt/custom-vpn && cd /opt/custom-vpn
   ./vpn.sh install-docker             # если docker еще нет
   cp .env.example .env && nano .env   # DOMAIN, ACME_EMAIL
   ./vpn.sh deploy                     # sysctl, ключи, первый пользователь, запуск, ссылки
   ```

`./vpn.sh` без аргументов показывает справку.

`deploy` генерирует ключи REALITY в `.env`, создает пользователя `default` в `users.conf`, ставит таймер `vpn-maintenance.timer` (чистит просроченные ключи после ротации и проверяет здоровье, см. «Мониторинг») и выводит ссылки.

Перед запуском `up` проверяет, что нужные порты (`VLESS_PORT`/tcp, `HYSTERIA_PORT`/udp, `SUB_PORT`/tcp, `ACME_HTTP_PORT`/tcp) не заняты чужими процессами — например, если на сервере уже есть сайт. Если заняты — пишет кем и что делать с каждым портом, и ничего не запускает:

- `SUB_PORT` / `HYSTERIA_PORT` — просто поменять в `.env`. Порт подписки входит в ссылку, после смены всем придется импортировать подписку заново; порт hysteria клиенты получат при обновлении подписки.
- `VLESS_PORT` (443/tcp) — другой HTTPS-сайт, см. «443/tcp занят сайтом».
- **80/tcp** — Let's Encrypt проверяет домен только через 80. Caddy держит его постоянно (а не только при выпуске), чтобы его нельзя было незаметно занять между продлениями. Если 80 нужен другому веб-серверу — `ACME_HTTP_PORT=8880` в `.env`, и этот сервер пробрасывает `/.well-known/acme-challenge/` для `DOMAIN` в caddy (`up` печатает готовый пример для nginx).

После запуска `up` проверяет, что запрос на `http://DOMAIN/.well-known/acme-challenge/<секрет>` через порт 80 действительно доходит до caddy.

## 443/tcp занят сайтом

Hysteria 2 работает по UDP и с сайтом не конфликтует (если у nginx не включен HTTP/3 на 443/udp). Для VLESS:

- **другой порт**: `VLESS_PORT=8444` (любой свободный) в `.env` — сайт не трогаем, но REALITY не на 443 выглядит менее естественно;
- **маршрутизация по SNI**: nginx `stream` на 443 отдает соединения с SNI `REALITY_SNI` в sing-box, остальное — сайтам. В `.env` — `VLESS_LISTEN=127.0.0.1:8444` (там слушает sing-box; в ссылках остается `VLESS_PORT=443`). Готовый конфиг nginx `up` печатает, если 443 занят: блок `stream` (нужен пакет `libnginx-mod-stream`) и замена `listen 443 ssl` у сайтов на `listen 127.0.0.1:4443 ssl proxy_protocol` + `real_ip_header proxy_protocol` — сайты продолжают видеть настоящие адреса посетителей. sing-box PROXY protocol не понимает, поэтому его ветка идет через промежуточный `server`, который заголовок снимает. `check` проверяет, что SNI `REALITY_SNI` на 443 доходит до sing-box.

Маскировки под свой сайт (self-steal, `REALITY_XVER`) больше нет: sing-box не умеет передавать сайту PROXY protocol, и сайт видел бы всех посетителей как `127.0.0.1`. Установка с `REALITY_XVER=1` при обновлении остановится на `init` с подсказкой; до исправления `.env` работает старая версия.

## Мониторинг

```sh
./vpn.sh check
```

Проверяет контейнеры, срок сертификата (меньше 14 дней — значит продления не проходят), путь Let's Encrypt через порт 80 и доступность `REALITY_SNI`. `vpn-maintenance.timer` раз в час запускает `prune` и `check`; если что-то сломалось, сервис падает — видно в `systemctl --failed` и `journalctl -u vpn-maintenance`.

**Бэкапить нужно `.env` и `users.conf`**, а если есть маршруты — еще `exits.conf`, `groups.conf`, `routing.conf` (на exit'е — `.env` и `hubs.conf`) — все остальное воспроизводится из репозитория. С ними на новом сервере клиенты продолжат работать, достаточно перенести A-запись.

## Exit (ROLE=exit)

Exit — сервер, через который хаб выпускает трафик пользователей. На нем только sing-box: VLESS REALITY для хабов и выход через `EXIT_IPS`. Домен, сертификат и пользователи не нужны.

```sh
git clone <repo> /opt/custom-vpn && cd /opt/custom-vpn
./vpn.sh install-docker    # если docker еще нет
ROLE=exit ./vpn.sh deploy  # ключи, EXIT_IPS, запуск
./vpn.sh hub add main      # печатает команду с токеном для хаба
```

- `EXIT_IPS` — IP, с которых уходит трафик, в виде `ИМЯ=IP` через запятую; `init` находит публичные IPv4 хоста сам и называет их `ip1`, `ip2`, ... Хаб знает IP только по имени (маршрут `EXIT/ИМЯ`), так что IP можно заменить здесь, не трогая маршруты на хабе. Новый IP или новое имя: поправить `.env`, `./vpn.sh up`, затем `./vpn.sh hub token main` и на хабе `./vpn.sh exit add ...` с новым токеном.
- У хаба свой ключ на каждый IP: какой IP, хаб выбирает ключом, поэтому exit ничего не знает о пользователях хаба. Трафик уходит только с IP своего ключа, маршрута по умолчанию нет. IPv6 закрыт (выход только с IPv4 из `EXIT_IPS`), приватные сети и адреса самого exit'а — тоже.
- `REALITY_SNI` лучше выбрать правдоподобный для страны и хостинга exit'а: участок хаб → exit проходит через DPI.
- `check` проверяет каждый IP: запрашивает внешний адрес через локальный socks (`CHECK_PORT`, только 127.0.0.1) и сверяет с ожидаемым.
- `hub del NAME` — хаб сразу перестает подключаться; `hub list` — хабы и их IP.

## Маршруты (хаб)

Трафик в RU уходит прямо с хаба у всех. Остальное — по маршруту пользователя:

| Маршрут | Куда |
|---|---|
| `local` | с самого хаба |
| `none` | никуда: работает только RU |
| `EXIT/ИМЯ` | через exit `EXIT` с его IP по имени `ИМЯ` |

Маршрут пользователя — его собственный, иначе маршрут его группы, иначе `ROUTE_DEFAULT` из `.env` (по умолчанию `local`, как у одиночного сервера; `none` или пусто — без интернета, кроме RU). Если маршрута нет (exit удален, IP переименован), трафик никуда не уходит: тихого переключения на другой IP нет, `check` и `exit add` об этом говорят.

```sh
./vpn.sh exit add cz1 'cvpn-exit:...'        # токен от ./vpn.sh hub add на exit'е; маршруты cz1/ip1, cz1/ip2
./vpn.sh group add sales cz1/ip1              # группа с общим маршрутом
./vpn.sh user add ivan --group sales          # или --route cz1/ip2
./vpn.sh user route ivan cz1/ip2              # свой маршрут сильнее группы; - — снова маршрут группы
./vpn.sh user group ivan -                    # убрать из группы
./vpn.sh route list                           # кто через что выходит и почему
```

- Что считается RU: имена `.ru`, `.su`, `.рф` и список `geosite-category-ru` (yandex.com, vk.com, 2gis и т. п.), а также соединения по IP к российским адресам (`geoip-ru`). Списки — от SagerNet, лежат в `data/rule-sets/`, таймер обновляет их раз в сутки (`./vpn.sh update rules` — сразу); если GitHub с хаба недоступен, они скачиваются через exit.
- То, что уходит с хаба, хаб резолвит сам (и блокирует имена, указывающие на приватные сети и на сам хаб). На exit уходит имя, exit резолвит его сам, из своей страны.
- Файлы: `exits.conf` (токены exit'ов), `groups.conf`, `routing.conf` (группа и маршрут пользователя) — их тоже нужно бэкапить.
- `check` проверяет каждый маршрут через локальный socks (`CHECK_PORT`): `local` и каждый `EXIT/ИМЯ` выходят со своего IP, `none` не выходит никуда, а RU и с ним выходит с хаба; а также свежесть списков RU и пользователей с несуществующим маршрутом.

## Пользователи и подписки

У каждого пользователя свои ключи и своя ссылка на подписку:

```sh
./vpn.sh user add vasya    # создать и показать ссылки (+ QR, если стоит qrencode)
./vpn.sh user list
./vpn.sh links vasya       # показать ссылки еще раз
./vpn.sh user del vasya    # ключи и подписка перестают работать сразу
```

- `https://DOMAIN:8443/<token>/sub` — подписка (base64-список `vless://` + `hysteria2://`). Подходит для любого клиента: «Добавить подписку» → вставить URL. Клиенты сами ее обновляют, так что новые ключи и настройки дойдут до них без переимпорта.
- `https://DOMAIN:8443/<token>/` — страница с кнопками, которые сразу открывают приложение и добавляют подписку:

  - Hiddify — `hiddify://import/<url>#<name>`
  - NekoBox — `sn://subscription?url=<url>&name=<name>`
  - V2Box — `v2box://install-sub?url=<url>&name=<name>`

Все, кроме токенов пользователей, отдает 404. Добавление/удаление пользователя перезапускает sing-box — у всех на секунду рвется соединение, клиенты переподключаются сами.

### Ротация ключей

```sh
./vpn.sh rotate vasya             # новые ключи, старые работают еще 24 часа
./vpn.sh rotate --all --grace 48  # всем, старые работают 48 часов
```

Ссылка на подписку не меняется. Пока старые ключи работают, клиенты успевают обновить подписку через еще живой туннель — не нужно отключать VPN, чтобы ее обновить. Просроченные ключи удаляет `vpn-maintenance.timer` (раз в час).

Если ссылка **утекла** — `rotate` не поможет (по старой ссылке получат и новые ключи): `user del` + `user add` и отправить человеку новую ссылку.

## Обновление

```sh
./vpn.sh update images   # новые версии sing-box / caddy
./vpn.sh update repo     # новый код этого репозитория с GitHub
```

`update images` показывает новые версии, спрашивает и обновляет. Образы, которые уже вышли на GitHub, но еще не опубликованы в registry, пропускаются. Если с новой версией конфиг не проходит проверку или контейнеры не стартуют — версии в `.env` откатываются.

`update repo` забирает `main` из публичного репозитория (`REPO_URL` / `REPO_BRANCH` в `.env`, чтобы поменять), показывает новые коммиты и файлы, которые изменятся, предупреждает о перезапуске контейнеров и спрашивает. Каталог, развернутый без git, при первом запуске становится git-checkout'ом (git ставится сам). Состояние сервера не трогается: `.env`, `users.conf`, `data/` (сертификаты) и `generated/` — перед обновлением `.env` и `users.conf` копируются в `backups/`, после — сверяются; если upstream вдруг начнет их отслеживать, обновление откажется. Локальные правки отслеживаемых файлов (шаблоны, `compose.yaml`) будут потеряны — об этом тоже предупредит.

## Firewall (опционально)

```sh
./vpn.sh firewall --dry-run   # только показать план
./vpn.sh firewall             # включить ufw
```

Открывает ssh (порт берется из sshd), порты VPN и спрашивает про остальные сервисы, которые сейчас слушают публичные адреса (другой сайт и т.д.), — по умолчанию оставляет их доступными. Все остальное входящее закрывается. Затем предлагает отключить вход по SSH-паролю — только если в `authorized_keys` есть ключи.

## Удаление

```sh
./vpn.sh uninstall      # спрашивает, что оставить
./vpn.sh uninstall -y   # все до чистого состояния
```

Всегда убирает то, что нужно только VPN: контейнеры, `vpn-maintenance.timer`, настройки sysctl (возвращает значения, которые были до первого `tune`). Дальше спрашивает:

| Что | По умолчанию |
| --- | --- |
| образы sing-box / caddy | удалить |
| правила ufw от `firewall` (если ufw был выключен до него — выключить обратно; иначе удалить наши правила, ssh оставить) | удалить |
| вход по SSH-паролю (если `firewall` его отключал) | не трогать |
| ключи, пользователи, сертификаты (`.env`, `users.conf`, `data/`, `generated/`, `backups/`) | оставить — `./vpn.sh deploy` поднимет тот же VPN с теми же ссылками |
| docker (если его ставил `install-docker`) | оставить |

Что менял на хосте, `vpn.sh` записывает в `/var/lib/custom-vpn`. Установки, сделанные до этой версии, не знают исходных значений sysctl (останутся до перезагрузки) и того, ставил ли docker `install-docker` (не предлагается удалить). Сам каталог репозитория остается: `rm -rf` его вручную.

## Команды

| `./vpn.sh …`                        |                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `help` (по умолчанию)               | справка                                                                  |
| `deploy`                            | `tune` + `init` + `up` + таймер + `links`                                |
| `init`                              | создать `.env`, догенерировать ключи, создать первого пользователя       |
| `up`                                | `render` + проверка портов + запуск/перезапуск измененных сервисов       |
| `down` / `logs`                     | остановить / смотреть логи                                               |
| `user add\|del\|list`               | пользователи (`user add NAME --group G --route R`)                       |
| `user route\|group NAME X`          | свой маршрут / группа пользователя (`-` — убрать)                        |
| `exit add\|del\|list`               | exit'ы хаба; их IP становятся маршрутами `EXIT/ИМЯ`                      |
| `group add\|route\|del\|list`       | группы с общим маршрутом                                                 |
| `route list`                        | кто через какой маршрут выходит                                          |
| `hub add\|token\|del\|list`         | хабы, которые пользуются этим exit'ом (`ROLE=exit`)                      |
| `links [NAME]`                      | ссылки всех пользователей или одного                                     |
| `rotate NAME\|--all [--grace H]`    | новые ключи, старые работают еще H часов (24)                            |
| `update images`                     | обновить образы до последних версий                                      |
| `update repo`                       | обновить код с GitHub (пользователи и ключи сохраняются)                 |
| `update rules`                      | скачать списки RU заново (таймер делает это раз в сутки)                 |
| `firewall [--dry-run]`              | ufw + отключение SSH-пароля                                              |
| `tune`                              | BBR + увеличенные UDP-буферы (`/etc/sysctl.d/99-vpn.conf`)               |
| `render`                            | собрать `generated/*` из `templates/*`, проверить конфиги sing-box и caddy |
| `check`                             | здоровье: контейнеры, сертификат, путь Let's Encrypt, `REALITY_SNI`, на хабе — каждый маршрут и списки RU, на exit'е — каждый `EXIT_IPS` |
| `prune`                             | удалить просроченные ключи, обновить списки RU (это и `check` делает таймер) |
| `install-docker`                    | поставить docker через get.docker.com                                    |
| `uninstall`                         | убрать все, что поставил `vpn.sh` (см. «Удаление»)                       |

`-y` — ответить «да» на все вопросы (для скриптов).

Поменять настройки: правим `.env` или `templates/*`, затем `./vpn.sh up`.

## Переезд с версии на xray + hysteria

`./vpn.sh update repo` — и все. `init` переименует ключи в `.env` (`XRAY_PORT` → `VLESS_PORT`, `XRAY_*_KEY` / `XRAY_SHORT_ID` → `REALITY_*`) и уберет `XRAY_IMAGE` / `HYSTERIA_IMAGE`, `up` заменит контейнеры xray и hysteria на sing-box. Ключи, пользователи и ссылки остаются прежними, клиенты переподключаются сами за пару секунд. Для сборки конфига нужен `jq` — `init` поставит его сам.

## Переезд с systemd-установки

Если xray и hysteria стоят как systemd-сервисы, они держат порты (`up` об этом скажет):

```sh
systemctl disable --now xray hysteria-server
./vpn.sh deploy
```

Однопользовательский `.env` (с `XRAY_UUID` / `HYSTERIA_PASSWORD` / `SUB_TOKEN`) `init` переносит в пользователя `default` с той же ссылкой на подписку. VLESS продолжит работать сразу, hysteria — после обновления подписки в клиенте (формат авторизации поменялся на `user:password`).
